# Data fetching

Data fetching is generated by Kubb.

> [!IMPORTANT]
> The backend is still in progress. Errors are expected if used now.
>
> For the meantime, you can use the generated mocks, which are
> [faker](https://fakerjs.dev/)-backed factory functions under `src/gen/<service>/mocks/`.
> Each returns a fully-typed object filled with random fake data and accepts an
> optional partial override. **Because they're generated from the committed OpenAPI
> specs, the shape is exactly what the backend expects.**

```ts
import { createProductDto } from '@/gen/product-service/mocks/createProductDto'

// Random data
const product = createProductDto()

// Random data with specific fields overridden
const knownProduct = createProductDto({ id: 'p-123', name: 'Cartesian 120 Storage' })
```

> [!NOTE]
> OpenAPI specs are committed under `openapi/`. Regenerate client code and docs from them with `npm run gen:all`, then access docs with `npm run serve:docs`.
>
> To refresh the committed specs from running servers, run `npm run gen:specs` (requires the backend at `/v3/api-docs`, e.g. [http://localhost:8083/v3/api-docs](http://localhost:8083/v3/api-docs)).

## Generated files (`src/gen/<service>/`)

| Path | What it is |
|------|------------|
| `clients/` | One typed async function per endpoint (`getChatHistory`, `createOrder`, …) |
| `hooks/` | React Query wrappers (`…QueryOptions`, `…MutationOptions`) |
| `types/`, `zod/` | Generated types + runtime schemas per operation |
| `.kubb/client.ts` | Shared client (native `fetch` transport) with `client`, `setConfig`, `getUrl`, interceptors |

## Examples

Every generated function takes one object of options:

| Option | Result | Spring Boot Equivalent |
|--------|--------| ---------------------- |
| `path` | URL path — `{ sessionId: 'abc-123' }` → `/agent/chat/abc-123` | @PathVariable |
| `query` | Query string — `{ userId: 'u-1' }` → `?userId=u-1` | @RequestParam |
| `body` | Request body (POST/PUT) | @RequestBody |
| `headers` | Set at the client level (see [Base URL](#base-url)) | @RequestHeader |

> [!TIP]
> Use `useQuery` for GET, `useMutation` for POST/PUT/DELETE.

> [!TIP]
> Function names are suffixed `QueryOptions` → `useQuery`, or `MutationOptions` → `useMutation`.

### GET — path param

```tsx
import { useQuery } from '@tanstack/react-query'
import { getChatHistoryQueryOptions } from '@/gen/agent-service/hooks/useGetChatHistory'

const { data, isLoading, isError, error } = useQuery(
  getChatHistoryQueryOptions({ path: { sessionId: 'abc-123' } })
)
// GET /agent/chat/abc-123
```

### GET — query params

```tsx
import { useQuery } from '@tanstack/react-query'
import { getOrdersByUserIdQueryOptions } from '@/gen/order-service/hooks/useGetOrdersByUserId'

const { data } = useQuery(
  getOrdersByUserIdQueryOptions({ query: { userId: 'u-1', shopId: 's-2' } })
)
// GET /orders?userId=u-1&shopId=s-2
```

### POST — body

```tsx
import { useMutation } from '@tanstack/react-query'
import { createOrderMutationOptions } from '@/gen/order-service/hooks/useCreateOrder'

const mutation = useMutation(createOrderMutationOptions())
mutation.mutate({ body: { /* OrderRequestBody */ } })
// POST /orders
```

## Loading & error state

`useQuery` returns flags you check in the component:

- `isLoading` — `true` while the first request is in flight (no data yet).
- `isError` — `true` when the request failed.
- `error` — the thrown error (a `ResponseError` with `status` and `data`).

```tsx
if (isLoading) return <p>Loading…</p>
if (isError) return <p>Error: {error?.status}: {error?.message}</p>;

return <ChatHistory items={data} />
```

`throwOnError` defaults to `true`, so a non-2xx response becomes `error`.

## Base URL

Generated clients carry no base URL. Set it in `src/lib/api.ts`.

```ts
import { client } from '@/gen/agent-service/.kubb/client'

client.setConfig({ baseURL: process.env.NEXT_PUBLIC_AGENT_SERVICE_URL })
```

Or per call: `getChatHistory({ baseURL, path: { sessionId } })`.
